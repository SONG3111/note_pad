# Bug 修复记录

> 开发过程中发现并修复的问题汇总,按模块分类。每条包含:现象 → 根因 → 修复 → 验证方式。

---

## 一、窗口停靠(贴边隐藏)

### 1.1 托盘点击/快捷键唤出后窗口"闪一下就没了"

- **现象**:窗口贴边隐藏时,点击托盘图标或按全局快捷键,窗口似乎毫无反应。
- **根因**:唤出逻辑只把目标位置设为"展开",但下一帧的常规逻辑「光标不在窗口内 → 自动收回」立即生效。用户的光标还在任务栏附近,展开动画刚起步就被拉回隐藏态。
- **修复**(`dock.rs`):引入 `force_until_hover` 状态——由托盘/快捷键触发的强制展开会**挂起自动收回**,直到光标真正进入过窗口一次,才恢复常规的离开即收回。
- **验证**:贴边 → 点托盘 → 窗口完整弹出并保持;光标进入窗口再移出后才收回。

### 1.2 贴边弹出被其他应用遮挡

- **现象**:便签贴边隐藏后点击其他软件,再把鼠标移回屏幕边缘,窗口弹出了但看不见。
- **根因**:z 序问题——弹出窗口位于当前活跃应用之下,被完全盖住,视觉上等于没弹。
- **修复**(`dock.rs`):吸附成功时对窗口调用 `set_always_on_top(true)`(置顶但不抢焦点,不影响其他应用打字);拖离边缘解除停靠时还原为普通层级。
- **验证**:贴边 → 激活任意全屏应用 → 鼠标移向屏幕边缘 → 便签浮在所有应用上方弹出。

### 1.3 macOS 不允许窗口移出屏幕(设计规避)

- **背景**:WindowServer 会强制窗口留在可见区域内,`set_position` 移出屏外会被拉回,导致"露出条"方案失效。
- **决策**:贴边隐藏功能限定 Windows 平台先做;macOS 需要走 `NSPanel` + `collectionBehavior` 原生路线,列为后续工作。

## 二、系统集成

### 2.1 全局快捷键注册冲突导致启动崩溃

- **现象**:`Ctrl+Alt+T/N` 注册时报 `HotKey already registered`,进程直接 panic 退出。
- **根因**:全局热键是系统级独占资源。已安装的正式版仍在后台运行并持有热键,新实例(开发版)注册同一热键被系统拒绝;代码里 `.expect()` 把注册失败当成致命错误。
- **修复**:
  1. 注册失败降级为 `eprintln!` 警告,应用正常启动(仅损失快捷键功能);
  2. 引入 `tauri-plugin-single-instance`:重复启动不再开第二个进程,而是聚焦已有窗口,从源头消除双实例争用。
- **验证**:保持正式版运行的情况下启动开发版,窗口正常打开且无崩溃。

### 2.2 托盘左键单击/双击无响应

- **现象**:隐藏到托盘后,单击/双击托盘小图标无法唤出主界面,必须右键菜单。
- **根因**:初版只注册了菜单事件,没有处理托盘图标自身的点击事件;且托盘事件分 Click / DoubleClick 两个变体,只匹配其一会有遗漏。
- **修复**(`lib.rs`):`.on_tray_icon_event` 同时匹配 `Click{Left, Up}` 与 `DoubleClick{Left}`,统一触发显示主窗口。

## 三、数据层(Rust / SQLite)

### 3.1 更新接口无法清空可选字段(title/content/color)

- **现象**:把标题清空后保存,重新打开发现旧标题还在。
- **根因**:serde 对 `Option<Option<T>>` 的默认行为里,JSON `null` 和字段缺失都会反序列化成外层 `None`,服务端无法区分「不修改」和「清空」。
- **修复**(`db.rs`):自定义 `double_option` 反序列化器——缺失→`None`(不改),显式 null→`Some(None)`(清空),有值→`Some(Some(v))`(更新)。前端配套约定:不传该键 = 不修改,传 null = 清空。

### 3.2 新建空记录残留空卡片

- **现象**:点了「＋待办」但什么都没输入就关闭编辑器,列表里留下一张空白卡片。
- **根因**:创建动作发生在打开编辑器之前,关闭路径没有任何"是否有效"的判断。
- **修复**:`NoteEditor` 关闭时上报 `isEmpty`(标题、正文、条目全空),父组件据此静默删除这条未成形的记录。
- **验证**:新建 → 直接 Esc/✕ 关闭 → 列表无新增。

## 四、前端交互(Vue)

### 4.1 待办卡片展开/收起状态切 tab 后丢失

- **现象**:收起某张待办卡,切到便签 tab 再回来,卡片又变成展开状态。
- **根因**:展开状态存在组件本地 `ref` 里,tab 切换导致组件卸载重建,state 归零。
- **修复**:状态提升到 Pinia store,按笔记 id 记录于 `expandedMap`;组件改为 computed get/set 读写 store。默认值仍是展开。

### 4.2 置顶便签在「全部」tab 下不置顶

- **现象**:便签加了 📌,在全部列表里仍排在未置顶待办之后。
- **根因**:排序键优先级是 类型 > 置顶 > 时间,类型分组压过了置顶意图。
- **修复**:调整优先级为 **置顶(不分类型)> 类型分组(同层级内待办在前)> 时间倒序**。

### 4.3 悬停操作按钮遮挡卡片标题

- **现象**:长标题卡片悬停时,右上角浮现的 ✎📌✕ 按钮组压在标题文字上。
- **修复**:卡片顶部预留 34px 操作带(padding-top),标题/内容整体下移;角标与按钮组互斥显示(非悬停显示角标,悬停显示按钮)。

## 五、构建与环境

### 5.1 NSIS 打包报 `timeout: global`

- **现象**:`tauri build` 时 MSI 成功,NSIS 阶段下载 `nsis_tauri_utils.dll` 反复超时失败。
- **根因**:Tauri 内置下载器有总超时预算;大文件(NSIS 主包 2.3MB)耗尽预算后,34KB 的插件 DLL 被掐断。且缓存目录校验"缺文件即整目录重建",手动预放的 DLL 也会被清掉。
- **修复**:并发注入——后台跑打包,前台脚本每 300ms 轮询,检测到 zip 解压完成(makensis.exe 出现)立刻补入 DLL,赶在校验前就位。
- **详见**:[打包指南](../方案/打包指南.md)(本地文档)

### 5.2 dev 启动报 `EADDRINUSE: 1420` / 进程互相残杀

- **现象**:重启 `tauri dev` 报端口占用;或应用启动后莫名退出(exit code 0xffffffff)。
- **根因**:上一次 dev 会话的 vite/cargo 监视进程成为孤儿存活,占用 1420 端口;新旧两个 `tauri dev` 会话同时运行时互相 kill 对方编译出的 exe。
- **修复流程**(已固化为操作步骤):
  ```powershell
  # 1. 清理孤儿进程树(node/vite、cargo、note_pad)
  Get-CimInstance Win32_Process -Filter "Name='node.exe' OR Name='cargo.exe'" |
    Where-Object { $_.CommandLine -match "vite|tauri" } |
    Remove-Process -Force
  # 2. 确认 1420 端口空闲后再启动
  npm run tauri dev
  ```
- **教训**:杀 `note_pad.exe` 不等于结束 dev 会话,**要连 cmd→npm→vite 整棵进程树一起清理**。

### 5.3 脚手架 `--force` 清空已有目录

- **现象**:`create-tauri-app --force` 执行后,项目内已有的 `docs/` 目录消失。
- **根因**:该参数语义是"清空目标目录后创建",并非"合并跳过已存在文件"。
- **教训**:向非空目录执行脚手架/生成类命令前,先备份或改在临时目录生成后手动合并。

## 六、独立便签窗口(拖出功能)

### 6.1 独立窗口右上角 ✕ 点击无反应

- **现象**:独立便签窗口点关闭按钮,窗口纹丝不动,控制台也无明显报错。
- **根因**:Tauri v2 的安全模型是「默认拒绝一切」——前端调用的每个 API 都需要在 `capabilities/default.json` 中显式授权。`close()` 所需的 `core:window:allow-close` 没有配置,调用被静默拒绝。
- **修复**:capabilities 的 permissions 数组补上 `"core:window:allow-close"`;同时 `windows` 字段加入 `"note-*"` 通配,让动态创建的独立窗口也纳入能力授权范围。
- **教训**:Tauri v2 里任何「调用了但没反应、也不报错」的 API,第一反应查 capabilities。

### 6.2 通过按钮拖出时系统假死

- **现象**:点击卡片上的「⧉ 拖出」按钮后,整个系统陷入假死,只能任务管理器杀进程。
- **根因**:`start_dragging()` 在鼠标按键**未按下**时被调用——Windows 上这会触发一个没有鼠标捕获的模态移动循环(SC_MOVE),卡死该窗口乃至系统的消息泵。拖拽手势路径没事,因为手势发生时鼠标必然按着。
- **修复**(`lib.rs`):`detach_note_window` 增加 `drag` 参数区分来源——拖拽手势(鼠标按住)传 true 才执行 `start_dragging()` 无缝续拖;按钮路径传 false,跳过拖动循环,窗口仅在光标处生成。
- **验证**:两条拖出路径各测一次,均正常且不再假死。

### 6.3 待办列表撑爆独立窗口布局

- **现象**:待办项较多时,独立窗口内列表把底部「添加输入框」「颜色选择」直接顶出窗外裁掉,列表也无法滚动。
- **根因**:flex 链断裂——`.todo-editor` 没有 `flex:1; min-height:0`,高度被内容无限撑开,内部 `.scroll-area` 的 `flex:1` 形同虚设,超出部分被 `.body` 的 `overflow:hidden` 裁剪。
- **修复**:补全弹性链 `.body(overflow hidden) → .todo-editor(flex:1, min-height:0) → .scroll-area(flex:1, overflow-y:auto)`,输入框与颜色栏 `flex:none` 固定底部;滚动条隐藏用 `scrollbar-width:none + ::-webkit-scrollbar{display:none}`。
- **经验**:嵌套滚动区域里,**每一层 flex 子项都要 `min-height:0`**,少一层就会退化成 content-size。

### 6.4 透明圆角窗口出现白边/黑角

- **背景**:独立窗口要做圆角效果,仅 CSS `border-radius` 不够——窗口本体不透明时四角仍是方形色块。
- **修复组合拳**(`lib.rs` + `NoteWindowApp.vue`):
  1. Builder 加 `.transparent(true)`(配合已有的 `.shadow(false)`);
  2. 全局重置 `html,body,#app { margin:0; height:100%; background:transparent }`(否则 body 默认 margin 露出白边);
  3. 根节点 `.nwin` 设 `border-radius:14px; overflow:hidden`,四周留 4px 透明边距给圆角和内描边阴影渲染空间。

## 七、稳定性与性能(Windows 卡死专项)

### 7.1 应用整体冻结/死机(删除独立窗口的记录时必现)

- **现象**:多窗口使用时偶发卡死;在主界面搜索到已拖出为独立窗口的便签并删除其记录时,整个应用冻结,只能任务管理器杀进程。
- **根因**(阅读 `tauri-runtime-wry` 源码确证):
  1. Tauri 在 Windows 上的窗口查询(`is_visible`/`outer_position`/`current_monitor` 等)是**同步跨线程往返**——调用线程发消息给主线程事件循环并阻塞等回复(`window_getter!` 宏);
  2. `dock.rs` 轮询循环**持着 `registry` 互斥锁**做这些阻塞调用;
  3. 主线程一旦需要同一把锁(如窗口销毁时 `dock::unregister`),两线程互相等待 → 死锁;
  4. 删除操作同时触发两个 WebView 的事件分发与 JS 重渲染,占住主线程,使冲突窗口必中。
  另有叠加因素:`list_notes`/`get_note` 为同步 command,直接阻塞主 UI 线程等数据库锁。
- **修复**(`dock.rs` + `lib.rs`):
  1. 轮询锁纪律重构:查询前先取 `WinState` 快照并立即释放锁,所有阻塞窗口查询在无锁状态进行,完成后写回(期间被注销则丢弃,不复活脏状态);
  2. 全部 command 异步化,数据库操作经 `spawn_blocking` 移至阻塞线程池,主线程永不阻塞;
  3. 轮询降频:动画帧 16ms→30ms,空闲查询 100ms→160ms 等,降低主线程消息泵压力;
  4. 单窗口轮询出错只降级该窗口(`?` 提前返回改为 match),不再中断整轮循环。
- **验证**:复现路径(搜索 → 删除已独立便签的记录)不再卡死;多窗口高频编辑流畅。
- **教训**:Tauri 里**绝不能在持有自己的锁时调用窗口 API**——那些调用可能反向等待主线程。

### 7.2 SQLite 无 WAL/busy_timeout,写入易被外部干扰阻塞

- **现象**:磁盘慢或文件被占用时写入卡顿甚至失败。
- **根因**:默认 rollback journal + `synchronous=full`,写入整库阻塞;Windows 上杀毒/同步软件锁文件时直接报错。
- **修复**(`db.rs` init):启用 `journal_mode=WAL` + `synchronous=NORMAL` + `busy_timeout=5000`(被占用时等待重试而非立即失败)。
- **验证**:数据库初始化正常,既有数据兼容。
- **教训**:数据库文件若位于 AppData 等被同步/扫描软件关注的目录,`busy_timeout` 是必需品。
- **备注**:软删除(`deleted_at`)记录尚无清理机制,数据库只增不减,列为后续工作。

## 八、多窗口数据同步与搜索联动

### 8.1 独立窗口关闭丢失最后输入的内容(正确性)

- **现象**:在独立窗口打字后立刻关闭,最后一段内容没有保存。
- **根因**:`closeWindow()` 里 `flushSave()` 是异步函数(防抖保存 600ms)但未 `await`,窗口在保存完成前即被销毁。
- **修复**(`NoteWindowApp.vue`):`await flushSave()` 后再执行后续逻辑与 `close()`。

### 8.2 独立窗口删除待办项后主列表不同步(隐藏 bug)

- **现象**:在独立窗口删掉一条待办项,主界面该卡片的列表不更新。
- **根因**:`delete_todo_item` 广播的 `notes-changed` 事件携带的是**待办项 id** 而非笔记 id,接收方 `get_note(项 id)` 失败后静默忽略。
- **修复**(`db.rs`):`delete_item` 返回所属笔记 id;`lib.rs` 据此广播。
- **验证**:独立窗口增/改/删待办项,主列表均实时同步。

### 8.3 跨窗口事件回拉风暴(性能)

- **现象**:每次自动保存,所有窗口(含发起者自己)都会再 `get_note` 回拉一遍,窗口越多 IPC 越重。
- **修复**(`lib.rs` + 两个前端入口):事件负载改为 `{ id, source }`,携带来源窗口标签;接收方跳过自己发出的变更。
- **附带**:浮动状态下消费掉陈旧的"强制唤出"标记,防止下次贴边停靠后意外弹出。
- **备注**:无分页,`list_notes` 全量返回,数据量大后需加分页,列为后续工作。

### 8.4 独立窗口中的便签搜索不到(功能缺陷)

- **现象**:便签拖出为独立窗口后,在主界面搜索它的内容无任何结果。
- **根因**:为避免与悬浮窗重复展示,列表渲染无条件过滤了 `detached` 便签,搜索也走同一列表。
- **修复**(`App.vue` + `NoteCard.vue` + `lib.rs`):抽出统一可见性规则 `inBoard`——搜索态召回已独立便签(带「独立窗口中」角标),非搜索态维持隐藏;点击这类卡片不开编辑器,而是复用 `detach_note_window` 的"已存在则聚焦"分支,并 `request_show` 唤出贴边隐藏的窗口。
- **验证**:搜索 → 带角标卡片出现 → 点击聚焦/唤出原窗口;清空搜索后恢复隐藏。

### 8.5 全部便签都已独立时误报"暂无数据"

- **现象**:上述功能首版上线后,所有便签都在独立窗口时搜索仍显示"暂无任何记录"。
- **根因**:列表(`boardNotes`)改了,但模板里决定是否渲染列表的 `tabPool`/`boardTotal` 仍无条件排除 `detached`,空状态判断先行命中。
- **修复**:列表、页签计数全部改用同一 `inBoard` 规则;不再使用的 `tabPool`/`boardTotal` 作为死代码删除。
- **教训**:同一业务规则在多处表达时,必须收敛为单一函数,否则改一处漏三处。

### 8.6 搜索无匹配时提示语错误(答非所问)

- **现象**:在"待办"页签搜索且无任何待办存在时,结果显示"暂无待办,添加任务来规划生活"——用户在搜索,却看到新建引导。
- **根因**:提示语按"当前页签是否有数据"分支,而非"是否在搜索"。
- **修复**(`App.vue`):按搜索态二分——搜索中永远显示"没有匹配「…」的记录"+副提示;非搜索才显示各页签引导语。

## 附:回归测试清单

每次发布前建议快速过一遍:

- [ ] 新建待办/便签,空内容关闭不留残留
- [ ] Todo 打勾、增删项、进度条正确
- [ ] 置顶便签在「全部」tab 排最上方;排序符合预期
- [ ] 切换 tab 后展开/收起状态保持
- [ ] 左右贴边吸附 → 悬停弹出 → 光标离开收回 → 拖离解除
- [ ] 贴边状态下点其他软件再回边缘,能正常弹出且不被遮挡
- [ ] 托盘单击/双击唤出;右键菜单显示/退出可用
- [ ] `Ctrl+Alt+T` / `Ctrl+Alt+N` 在任意前台应用下可唤出新建
- [ ] 主界面关闭(X)进托盘而非退出;托盘「退出」真正结束进程
- [ ] 卡片拖拽 / ⧉ 按钮两种方式均可拖出独立窗口,且无假死
