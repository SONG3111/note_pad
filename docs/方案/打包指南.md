# 打包指南与排障备忘

> 记录 note_pad 的打包流程,以及 2026-08-25 首次打包时 NSIS 工具下载失败的完整排障过程。

## 日常打包命令

```powershell
npm run tauri build                        # 全部格式(nsis + msi)
npm run tauri build -- --bundles nsis      # 只打 setup.exe,更快
npm run tauri build -- --version 0.2.0     # 顺便改版本号
```

`tauri build` 内部三阶段:

| 阶段 | 做什么 | 产物 |
|---|---|---|
| ① 前端构建 | `npm run build`(vue-tsc + vite) | `dist/` |
| ② Rust 编译 | cargo release 模式(首次约 3-4 分钟,之后增量几十秒) | `src-tauri/target/release/note_pad.exe` |
| ③ 打包封装 | exe + 图标 + WebView2 引导器 → 安装包 | `bundle/nsis/*.exe`、`bundle/msi/*.msi` |

### 产物说明(0.1.0 实测)

| 文件 | 大小 | 用途 |
|---|---|---|
| `bundle/nsis/note_pad_0.1.0_x64-setup.exe` | 2.7MB | 安装向导版,日常分发用 |
| `bundle/msi/note_pad_0.1.0_x64_en-US.msi` | 4MB | MSI 标准包,适合脚本/企业部署 |
| `target/release/note_pad.exe` | ~3MB | 免安装绿色版 |

安装版与开发版共用标识符 `com.songqulv.notepad`,数据同在 `%APPDATA%\com.songqulv.notepad\notepad.db`,互相兼容。

安装包名称/图标/语言等在 `src-tauri/tauri.conf.json` 的 `bundle` 字段配置。

## 排障记录:NSIS 打包 "timeout: global"(2026-08-25)

### 现象

首次执行 `npm run tauri build`:MSI 成功;NSIS 阶段反复报:

```
Info Verifying NSIS package
Downloading https://github.com/.../nsis-3.11.zip        ← 能成功
validating hash / extracting NSIS                       ← 能成功
Downloading https://github.com/.../nsis_tauri_utils.dll ← 必超时
failed to bundle project: `timeout: global`
```

### 根因

Tauri 首次 NSIS 打包需联网下载两个工具并缓存到 `%LOCALAPPDATA%\tauri\NSIS`:
NSIS 主程序 zip(2.3MB)和官方插件 DLL(34KB)。内置下载器有**总超时预算**,大 zip 耗尽预算后,轮到小 DLL 就被掐断。且每次启动时若校验发现缓存目录"缺文件",会**整个删除重下**,导致手动预放的 DLL 也被清掉,形成死循环。

### 解决:并发注入

利用流程时序差——「校验→删目录→下 zip→解压→查 DLL→使用」。后台跑打包,前台循环监控,**一旦 zip 解压完成(makensis.exe 出现)立刻把 DLL 复制进去**,Tauri 查 DLL 时发现已存在即跳过下载:

```powershell
$log = "$env:TEMP\opencode\nsis-build.log"
$dest = "$env:LOCALAPPDATA\tauri\NSIS"
Start-Process cmd "/c npm run tauri build -- --bundles nsis > $log 2>&1"

$injected = $false
for ($i=0; $i -lt 900; $i++) {
    if ((Test-Path "$dest\makensis.exe") -and -not $injected) {
        New-Item -ItemType Directory "$dest\Plugins\x86-unicode" -Force | Out-Null
        Copy-Item "<dll路径>\nsis_tauri_utils.dll" "$dest\Plugins\x86-unicode\" -Force
        $injected = $true
    }
    Start-Sleep -Milliseconds 300
}
```

DLL 手动获取方式(curl 支持重试,比 Tauri 内置下载器可靠):

```powershell
curl -sL --retry 3 -o nsis_tauri_utils.dll `
  "https://github.com/tauri-apps/nsis-tauri-utils/releases/download/nsis_tauri_utils-v0.5.3/nsis_tauri_utils.dll"
```

### 经验总结

1. 缓存目录 `%LOCALAPPDATA%\tauri\NSIS` 一旦完整生成,**之后打包不再联网**,秒过第三步——别手删它
2. 报 `timeout: global` 先看日志卡在哪个下载上;MSI(WiX)与 NSIS 相互独立,一个失败不影响另一个
3. 网络对 github release 资源时好时坏(codeload/raw 可用 ≠ release 资产可用),curl 重试比内置下载器稳
4. 同类问题通用思路:看清失败发生在哪个子步骤 → 找到缓存/校验机制 → 用时序或预置绕过下载环节
