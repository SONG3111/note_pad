# note pad — 实施方案

> 一款安装到电脑和手机的随手记录软件：记 idea、记待办、多端同步、桌面端贴边隐藏。

## 需求清单

| # | 需求 | 说明 |
|---|------|------|
| 1 | Todo List + 想法记录 | 待办可打勾；也支持纯文字便签随手记录 |
| 2 | 手机 ↔ 电脑同步 | 多端数据一致，离线可用，联网自动同步 |
| 3 | 贴边隐藏（桌面端） | 窗口拖到屏幕边缘自动收起，鼠标悬停时丝滑弹出 |

## 推荐技术栈(方案 A:Tauri 2 全家桶)

```
┌─ 共享前端 (Vue3/React + TypeScript) ─────────────┐
│   便签列表 │ Todo勾选 │ 编辑器 │ 设置            │
└──────────┬───────────────────┬──────────────────┘
     桌面端│Tauri 2 (Win/Mac)   移动端│Tauri 2 (iOS/Android)
           │                          │
┌─ Rust 核心 ──────────────────────────────────────┤
│  SQLite本地存储(tauri-plugin-sql)                │
│  窗口停靠模块(Win32: 吸附/隐藏/弹出动画)         │
│  同步引擎(变更日志+冲突解决)                     │
└──────────────────┬───────────────────────────────┘
                   │ HTTPS/WebSocket
        ┌─ 同步服务端 ──────────┐
        │ 方案1: Supabase(免运维)│
        │ 方案2: 自建 axum/Hono  │
        │       + Postgres(Docker)│
        └────────────────────────┘
```

### 选型理由

- 一个前端代码库覆盖电脑 + 手机(Tauri v2 已正式支持 iOS/Android)
- 安装包约 ~10MB,内存占用约为 Electron 应用的 1/10
- Rust 写窗口停靠性能好,且有现成参考(maestro-flow)
- 本产品是轻量便签而非富文本文档,不需要 AppFlowy 那么重的 CRDT 架构

### 备选方案对比

| 维度 | A. Tauri 2(推荐) | B. Electron+Expo RN | C. Flutter |
|---|---|---|---|
| 代码复用 | 高(一套前端全平台) | 中(TS 逻辑层共享) | 最高(纯单代码库) |
| 内存/体积 | ★ 最小(~10MB 安装包) | 最大(100MB+) | 小 |
| 贴边隐藏难度 | 中(Rust+Win32) | 低(现成代码最多) | 中高(要写平台通道) |
| 移动端成熟度 | 中(v2 较新) | ★ 最成熟 | ★ 成熟 |
| 同类产品 | maestro-flow | Joplin / Notesnook / Edge-Drop | AppFlowy |

选 B 的场景:重度依赖 RN 生态、想要最成熟的移动端。
选 C 的场景:未来想做复杂 UI 动画、愿意为贴边功能写 Windows 原生代码。

## 核心实现要点

### 1. 数据模型(SQLite)

```sql
-- 便签/待办主表
CREATE TABLE notes (
    id          TEXT PRIMARY KEY,        -- UUID v7
    type        TEXT NOT NULL,           -- 'note' | 'todo'
    title       TEXT,
    content     TEXT,                    -- 纯想法的正文(Markdown)
    color       TEXT,                    -- 便签颜色
    pinned      INTEGER DEFAULT 0,      -- 置顶
    sort_weight REAL,                    -- 手动排序权重
    created_at  INTEGER NOT NULL,
    updated_at  INTEGER NOT NULL,        -- LWW 冲突解决依据
    deleted_at  INTEGER                  -- 软删除,同步后物理清理
);

-- Todo 条目(一条 todo 便签下可有多个可勾选项)
CREATE TABLE todo_items (
    id         TEXT PRIMARY KEY,
    note_id    TEXT NOT NULL REFERENCES notes(id),
    text       TEXT NOT NULL,
    checked    INTEGER DEFAULT 0,
    sort_order INTEGER DEFAULT 0,
    updated_at INTEGER NOT NULL
);

-- 变更日志(同步队列)
CREATE TABLE sync_ops (
    seq          INTEGER PRIMARY KEY AUTOINCREMENT,
    entity_id    TEXT NOT NULL,
    entity_table TEXT NOT NULL,
    payload_json TEXT NOT NULL,
    device_id    TEXT NOT NULL,
    pushed_at    INTEGER
);
```

索引建议:`notes(updated_at)`、`todo_items(note_id, sort_order)`、`sync_ops(pushed_at)`。

### 2. 同步策略(MVP 够用即可)

**快速上线路线 —— Supabase**

- Auth:邮箱或匿名设备账号升级绑定
- Postgres 表结构与本地对齐;Realtime 监听变更做增量拉取
- 冲突处理:按 `updated_at` 做 last-write-wins;Todo 勾选按**条目粒度**合并(不同条目互不覆盖),日常使用基本无冲突
- 免费额度足够个人使用,免运维

**自托管路线 —— 数据自主**

- 一台 VPS + Docker 跑同步 API(Rust axum 或 Node Hono)+ Postgres
- 客户端逻辑不变,仅换 baseURL(Joplin Server 模式)

**进阶(可选)**:多人协作或高频编辑再引入 CRDT(Yjs / yrs),当前规模不必要。

同步触发时机:应用启动、数据变更后防抖 2s、从后台恢复、定时 5min 兜底。

### 3. 贴边隐藏(桌面独占,参考 HiddenWindow / Edge-Drop)

```
拖动中: 检测窗口距屏幕边缘 < 32px → 显示吸附预览提示
松手后: setBounds 移出屏外,只留 4~6px 露出条(reveal strip)
监听:   主进程轮询光标位置
        - 光标接近露出条: 150ms 间隔
        - 远离/空闲: 500ms 间隔退避(防止 CPU 占用)
弹出:   easeOutCubic 缓动分 8 步移动窗口,全程约 200ms,"丝滑"手感
收回:   光标离开窗口区域 → 缓动滑回隐藏态
解除:   用户把窗口拖离边缘 → 恢复普通窗口模式
持久化: 记住停靠边与位置,重启恢复
```

技术细节:

- Tauri 配置 `decorations: false`(无边框窗口),自绘标题栏
- Win32 侧用 `SetWindowPos` 分步移动;光标检测可用 `GetCursorPos` 轮询(跨平台简单)或 `SetWindowsHookEx(WH_MOUSE_LL)` 低级钩子(更精准但复杂)
- 与 Windows Snap(Aero Snap)冲突处理:停靠状态下禁用边缘 resize
- macOS 限制:WindowServer 不允许窗口移出屏幕,一期只做 Windows;macOS 用 `NSPanel` + `collectionBehavior` 是二期工作
